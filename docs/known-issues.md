## KI-1. FY2027 caveat: "may be lower than 44" next to an answer of 44

**Status:** open. Fix goes in after v2 merges, together with a dev eval rerun. `src/agent` is not changed on `v2`.

**Question:** "How many IBRD loans were approved in fiscal year 2027?" (eval D15, and the original cached example 4)

**Seen twice (exact text; the "lower than 44" sentence is identical both times):**

| When | Where | Assumption text |
|---|---|---|
| Nov 1, 2026 | dev eval, `eval/results/20261101-173749_dev.json`, D15 | "FY2027 is partial in this snapshot: only Jul 1 - Sep 30, 2026 is covered (44 loans and guarantees in total), so the count is not a full-year figure." / "Guarantees excluded (is_guarantee = FALSE), so the count may be lower than 44." |
| Nov 3, 2026 | `scripts/precompute_examples.py` run at `7eb04e8` (example 4, not published; replaced by D09) | "FY2027 is only partially covered: the snapshot ends 2026-09-30, so it only includes Jul-Sep 2026 approvals (44 loans and guarantees in total)." / "Guarantees excluded (is_guarantee = FALSE), so the count may be lower than 44." |

The answer was **44** both times, which is correct (gold: 44).

**Why it is wrong:**
- FY2027 has 44 rows and **0 guarantees**, so excluding guarantees can't lower the count. The answer can't be "lower than 44" when it is 44.
- For a partial year, the full-year count can only be the same or higher. "Lower" points the wrong way.

**Cause:** the dictionary says "FY2027 is partial (Jul-Sep 2026, 44 loans)" in two places (`board_approval_fy.data_check` and rule `fiscal_year`). The model sees 44 before writing its SQL, relabels it "44 loans and guarantees in total", and then guesses how excluding guarantees changes it. It writes assumptions before it sees the result, so a comparison like this is always a guess.

**Proposed fix (not applied).** One dictionary edit plus one prompt line:

1. `src/agent/data_dictionary.yaml`, rule `fiscal_year`:
   ```diff
   - FY2027 is partial (Jul-Sep 2026, 44 loans): flag it whenever a question touches FY2027.
   + FY2027 is partial (Jul-Sep 2026; 44 loans, 0 guarantees): flag it whenever a question touches FY2027.
   +   A partial-year figure covers only part of the year; the full-year figure can only be the same or higher.
   ```
2. `src/agent/prompt.py`, end of "Defaults":
   ```diff
   + - Assumptions describe what the SQL does. Don't predict how the result compares to a number:
   +   you write them before you see the result.
   ```

**After applying:** `cache_version` changes (it hashes the system prompt), so `server/tests/test_examples.py` will fail until `web/src/data/examples.json` is regenerated by `scripts/precompute_examples.py`. That re-runs all 4 examples, so it needs Khaled's OK under the "generated once, never reroll" rule. Then run `python scripts/run_eval.py --split dev` once and record it in `eval/RESULTS.md`.

### Scoring caveats for correctness, not just presence

Today `caveat_check` (`src/agent/scoring.py`) only checks that terms such as `partial` appear in the message or assumptions. D15 passed with the wrong caveat. Two small, deterministic additions, reported the same way as today and never changing the outcome:

1. **`must_not_mention`** in `eval/questions.yaml`, the mirror image of `must_mention`: any match is a caveat failure. For D15: `[["lower than", "fewer than", "less than", "may be lower", "undercount"]]`. It costs nothing, needs no model and catches this exact regression.
2. **A comparison-claim check** against the actual result: find phrases like `(lower|less|fewer|higher|more|greater|above|below|under|over) than <number>` in the text, and when the result is a single number, test the claim. A claim that "may be lower than X" fails when result ≥ X; one that "may be higher than X" fails when result ≤ X. This catches the same class of mistake on any question, not only D15.

An LLM judge would also work, but it adds cost and run-to-run noise to the eval. I'd add 1 and 2 first.
